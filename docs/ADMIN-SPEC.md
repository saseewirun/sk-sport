# SK-Sport Custom Admin — Specification (ฉบับออกแบบตาม UX ที่ตกลงกัน)

> **หลักออกแบบ (จาก Nofffie):** คนใช้ไม่ใช่ Dev — admin ต้อง "จัดตามหน้าเว็บ"
> ไม่ใช่ตาม collection แบบ Payload เดิมที่ลูกค้าหาไม่เจอ • ในแต่ละหน้า เรียง section
> **บน→ล่าง ตรงตามที่เห็นบนเว็บจริง** • ทุกช่องมีคำอธิบายไทยว่าคืออะไร/อยู่ตรงไหน
> • spec นี้จะใช้เป็นโครงของคู่มือลูกค้าด้วย

---

## 1) สถาปัตยกรรม

```
/admin (SPA, static, ภาษาไทยทั้งหมด)
   │  login ด้วยรหัสผ่านธรรมดา (ลูกค้าไม่ต้องรู้จัก GitHub เลย)
   ▼
Cloudflare Pages Functions (/api/admin/*)
   │  ตรวจรหัสผ่าน (env ADMIN_PASSWORD) → ออก session cookie
   │  ถือ GITHUB_TOKEN ฝั่ง server เท่านั้น (ลูกค้าไม่เห็น token)
   ▼
GitHub Contents API → commit ไฟล์ content/*.json + public/uploads/* + src/messages/th/*.json
   ▼
Cloudflare Pages auto-build → เว็บจริงอัปเดตใน ~2-3 นาที
```

- **Login:** หน้าเดียว ช่องรหัสผ่านช่องเดียว (ลูกค้าคุ้นเคยที่สุด) — token GitHub อยู่ใน env ของ Cloudflare ไม่ผ่าน browser
- **Save:** กดบันทึก → ขึ้นสถานะ "✅ บันทึกแล้ว — เว็บไซต์จริงจะอัปเดตภายใน 2-3 นาที"
- **อัปโหลดรูป:** เลือกไฟล์ → ย่อ/แปลง WebP ฝั่ง browser → function commit เข้า `public/uploads/<หมวด>/` (ชื่อไฟล์ sanitize อัตโนมัติ กันปัญหาชื่อไทยซ้ำรอยเดิม)
- **Env ที่ต้องตั้งใน Cloudflare:** `ADMIN_PASSWORD`, `GITHUB_TOKEN` (fine-grained, contents:write เฉพาะ repo นี้), `GITHUB_REPO=saseewirun/sk-sport`, `GITHUB_BRANCH=main`

## 2) เมนูหลักของ Admin (เรียงตามเมนูบนเว็บจริง)

```
🏠 หน้าแรก | 👥 เกี่ยวกับเรา | 🛠 บริการ | 📦 สินค้า | 🏆 ผลงาน | ☎️ ติดต่อเรา
❓ คำถามที่พบบ่อย | 📄 นโยบาย & ข้อกำหนด | 🧾 ประวัติการสั่งซื้อ | ⚙️ ตั้งค่าการชำระเงิน
```

ทุกหน้า admin = รายการ "การ์ด section" เรียงบน→ล่างตามเว็บจริง แต่ละการ์ดมี:
**ชื่อ section ภาษาไทย + คำอธิบาย "ส่วนนี้แสดงตรงไหน" + ช่องแก้ไข + ปุ่มบันทึกของการ์ดนั้น**

## 3) โครงสร้างรายหน้า (field → ไฟล์ต้นทาง)

| 7     | เกี่ยวกับบริษัท           | ชื่อบริษัท, รายละเอียด                                                        | `Home.json` → `AboutCompany.*`            |

### 👥 เกี่ยวกับเรา

1. รูป+ข้อความแบนเนอร์ (`about-hero.json`) → 2. ประวัติบริษัท: ชื่อ, คำบรรยาย, กล่องสถิติ (`about.json` history\*) → 3. พันธกิจ/วิสัยทัศน์ → 4. วิดีโอ YouTube (เพิ่ม/ลบลิงก์) → 5. **ทีมงาน (Team Member)**: รายชื่อ → กดแก้รายคน (ชื่อ, ตำแหน่ง, คำแนะนำสั้น, ประวัติเต็ม, คำคม, **รูปการ์ด**, แกลเลอรี) ← จุดที่ลูกค้าใช้บ่อยสุด (เคสรูป Nattanat) → 6. ขนาดตัวอักษร (`founders.json` + `about.json`)

### 🛠 บริการ

1. แบนเนอร์หน้ารวม (`services-hero.json`) → 2. รายการบริการ 5 รายการ → แก้รายตัว: ชื่อ, ชื่อรอง, รูปแบนเนอร์, เนื้อหาเป็น section (หัวข้อ+คำอธิบาย+รูปแบบกริด/แถว) (`services.json`) → 3. ขนาดตัวอักษร

### 📦 สินค้า

1. แบนเนอร์ (`products-hero.json`) → 2. รายการสินค้า 14 ชิ้น (ปุ่ม "+ เพิ่มสินค้าใหม่" บนสุด) → แก้รายชิ้น: ชื่อ, ชื่อรอง, หมวด, รูปแบบขาย (ใบเสนอราคา/ซื้อเลย), ราคา, คำอธิบาย, รูป (`products.json`; slug สร้างอัตโนมัติจากชื่อ — sanitize เป็น a-z0-9 เสมอ) → 3. ขนาดตัวอักษร

### 🏆 ผลงาน

1. แบนเนอร์ (`portfolio-hero.json`) → 2. รายการบทความผลงาน (+เพิ่มใหม่) → แก้รายตัว: ชื่อ, แท็ก, เป็นผลงานเด่น?, เนื้อหา, รูปหลัก, แกลเลอรี (`portfolio-articles.json`; slug sanitize — **ห้ามมี | / อักขระพิเศษ** ตาม bug ที่เจอ) → 3. ขนาดตัวอักษร

### ☎️ ติดต่อเรา

1. แบนเนอร์+ข้อความ (`contact-hero.json`) → 2. **ลิงก์ Google Map** (พร้อมวิธี copy จาก Google Maps ในคำอธิบาย) → 3. ข้อมูลติดต่อ (โทร/อีเมล/ที่อยู่/โซเชียล — `src/const/contact.ts` ⚠️ ต้องย้ายเป็น `content/globals/site-contact.json` ให้แก้ได้) → 4. ขนาดตัวอักษร

### ❓ คำถามที่พบบ่อย

1. ข้อความหัวหน้า → 2. รายการคำถาม-คำตอบ (เพิ่ม/ลบ/สลับ) → 3. กล่อง CTA ล่าง → 4. ขนาดตัวอักษร (`faq.json`)

### 📄 นโยบาย & ข้อกำหนด

แท็บ 2 อัน (Privacy / Terms): หัวข้อ, วันที่อัปเดต, เนื้อหาแบบ**กล่องข้อความหลายย่อหน้า** (แปลงเป็น lexical ให้อัตโนมัติ — ลูกค้าไม่ต้องรู้จัก rich text)

### 🧾 ประวัติการสั่งซื้อ (อ่านอย่างเดียว)

ตาราง: วันที่, ชื่อลูกค้า, เบอร์, สถานะ, ยอด → กดดูรายละเอียด + **รูปสลิป** • แหล่งข้อมูล: `content/collections/orders.json` (8 รายการเก่า) + ไฟล์ใหม่ใน `orders/` (จากฟอร์ม checkout ใหม่) • รวม quote-requests

### ⚙️ ตั้งค่าการชำระเงิน

เปิด/ปิดการโอน, ธนาคาร, ชื่อ/เลขบัญชี, สาขา, คำแนะนำ, รูป QR (`payment-settings.json`)

## 4) กติกาที่ต้องยึดตอน implement

1. ภาษาไทยทั้งหมด ทุก label มีบรรทัดคำอธิบายสีเทาใต้ชื่อช่อง (ใช้ description เดิมจาก payload collections เป็นต้นทาง — เขียนไว้ดีแล้ว)
2. ห้ามใช้ศัพท์เทคนิค: "slug"→"ที่อยู่ลิงก์ (สร้างให้อัตโนมัติ)", "media"→"รูปภาพ"
3. รูป: แสดง preview ปัจจุบันเสมอ + ปุ่ม "เปลี่ยนรูป" — ไม่มี media library แยก (ตัดปัญหากระโดดหน้า)
4. ทุกการบันทึกมี feedback ชัด: กำลังบันทึก… → ✅ บันทึกแล้ว เว็บอัปเดตใน 2-3 นาที / ❌ ผิดพลาด+วิธีแก้
5. ปุ่ม "ดูหน้าเว็บจริง" มุมขวาบนของทุกหน้า admin (เปิดหน้านั้นของเว็บใน tab ใหม่)
6. มือถือใช้ได้ (ลูกค้าอาจแก้จากมือถือ)
7. commit message อัตโนมัติเป็นไทย เช่น `แก้ไขหน้าแรก: เปลี่ยนรูปแบนเนอร์` (ใช้เป็น audit log ย้อนหลังได้)

## 5) API contract (Cloudflare Pages Functions)

```
POST /api/admin/login        {password} → set cookie (HMAC, หมดอายุ 24 ชม.)
GET  /api/admin/content?file=<path>           → อ่านไฟล์ล่าสุดจาก GitHub
PUT  /api/admin/content      {file, json, message} → commit 1 ไฟล์
POST /api/admin/upload       {folder, filename, base64, message} → commit รูป + คืน path
GET  /api/admin/orders                        → รวม orders เก่า+ใหม่
POST /api/checkout | /api/quote (public)      → เขียน orders/YYYY/<id>.json + สลิป + อีเมล Resend
```

## 6) ลำดับการ implement

1. ลบ `src/app/(payload)` (Payload หมดหน้าที่แล้ว — ข้อมูล export ครบ, เก็บ payload package ไว้เพื่อ export script) + ตั้ง `output:'export'`
2. โครง admin SPA: login + เมนู + ระบบการ์ด section (component กลาง ใช้ซ้ำทุกหน้า)
3. ทำ "หน้าแรก" ให้จบเป็นต้นแบบ → ไล่ทำหน้าที่เหลือตาม spec
4. ย้าย `src/const/contact.ts` → `content/globals/site-contact.json`
5. Functions: auth + content + upload + orders + checkout/quote ใหม่
6. ทดสอบทุกหน้าด้วยข้อมูลจริง → คู่มือลูกค้า (โครงตาม §3 + screenshot)
